How it works

Five stages, all of which you can watch from this page. A run takes about an hour on today's GPU.

  1. 1 · YOUR GOAL

    One sentence

    What the model should do, and how hard it should try before it's yours: quick, standard or strict.

  2. 2 · PLAN

    The Job Architect

    Checks the goal is something a small model can learn, then writes the training chats and test prompts it keeps hidden.

  3. 3 · TRAIN

    A fine-tune

    A LoRA add-on for Qwen3 0.6B, a small model that runs fast and cheap. Training moves onto Vibe Hash's miners next.

  4. 4 · JUDGE

    The Quality Judge

    Compares your model with the base model told your goal, blind and in both orders. Below the bar, it repairs and tries again.

  5. 5 · TRY IT

    A blind chat

    Ask both models anything. You see two answers, A and B, pick the better one, then learn which was yours.

What it has shown

Four runs from the first public trial, on one RTX 4060 with Qwen3 0.6B as the base. All of them are here, including the one that failed. Every answer is on results.luhlabs.com.

Reached the bar

Support tickets → one line of JSON

19/20won, none lost

81% of replies passed every format rule, against 3% for the model told the goal. It used 53% fewer prompt tokens and answered in 1.8 s instead of 3.4 s.

Short of its bar

Plain English → one Excel formula

11/19won, 8 ties, none lost

94% of replies passed the format rules, against 55%. The ties are short requests where both models wrote the same formula.

Quick level

Only woofs and barks

14/20won, 5 ties, 1 lost

Taught from a chat message. A second judge, a different model, read the same pairs and gave it 18 of 20.

Didn't work

Talk like Mark Twain, reason like Plato

5/18stopped

A small model learns a format well and a voice that needs reasoning badly. The Architect now warns about goals like this before any training.

Good fits

  • A fixed output format: JSON, one formula, one line, two sentences
  • Sorting or labelling text into categories you name
  • Politely declining anything that isn't its job
  • Replacing a long prompt you send with every request

Poor fits, for now

  • A writing voice that needs real reasoning
  • Wordplay and puns
  • Facts the base model doesn't already know
  • Anything that needs a large model's judgment
